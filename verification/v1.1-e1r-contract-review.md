## S1 — `cmc_simple_price`

- Description: “Get the latest simple CoinMarketCap price for a known set of cryptocurrencies, selected by exactly one of ids, slugs, or symbols. Prefer CMC IDs over symbols when identity ambiguity matters.”
- Arguments: exactly one of `ids` (`Ids`), `slugs` (`Slugs`), `symbols` (`Symbols`); `convert` (`UniqueConversions`, default `["USD"]`).
- Query: provider key `id`, `slug`, or `symbol` (comma-joined selector values) plus `convert` (comma-joined). Nothing else.
- Deliberately omitted provider parameters: `convert_id`, include flags, `precision`, `skip_invalid`.
- Verifier (documentation-derived, see C1): `data` is a non-empty list; each item has a positive non-bool integer `id` and non-empty `quotes`; at least one quote has a finite non-bool numeric `price`.

## S2 — `cmc_crypto_categories`

- Description: “Get a paginated list of CoinMarketCap cryptocurrency categories with their category IDs. Use cmc_crypto_category to fetch one category's coins.”
- Arguments: `start` integer ≥ 1, default 1; `limit` integer 1–100, default 100.
- Query: `start`, `limit`. Provider `id`/`slug`/`symbol` filters are omitted.
- Verifier: `data` is a non-empty list; each item has non-empty string `id` and `name`.

## S3 — `cmc_crypto_category`

- Description: “Get one CoinMarketCap cryptocurrency category and a paginated page of its coins with market quotes. Obtain category IDs from cmc_crypto_categories.”
- Arguments: required `id` string matching `^[A-Za-z0-9]+$`, length 1–64; `start` integer ≥ 1, default 1; `limit` integer 1–100, default 100; `convert` (`UniqueConversions`, default `["USD"]`).
- Query: `id`, `start`, `limit`, `convert` (comma-joined). `convert_id` is omitted.
- Verifier (see C2): `data` is a non-empty mapping; at least one value in `data` is a mapping with a non-empty string `id` and a `coins` list; `coins` may be empty. Outer map keys are provider-owned and are neither required to have a particular value nor interpreted.

## S4 — `cmc_price_conversion`

- Description: “Convert an amount of one source cryptocurrency, identified by exactly one of id or symbol, into exactly one target currency, identified by exactly one of convert or convert_id (USD if neither is given).” The description must contain “exactly one target currency”.
- `amount`: required; strict finite number (see C3); not bool, not string; 1e-8 ≤ amount ≤ 1e12.
- Source: exactly one of `id` (positive integer) or `symbol` (`ListToken`).
- Target: at most one of `convert` (`ListToken`) or `convert_id` (positive integer). No schema default for `convert`; when both are absent the handler sends `convert=USD` (see C4).
- Rejected before network: no source or both sources; both targets; comma-separated or list target; out-of-range, bool, string, NaN or infinite amount.
- Query: `amount` as a plain decimal string, never exponent notation (`1e-8` → `0.00000001`, `1e12` → `1000000000000`); source key `id` or `symbol`; target key `convert` or `convert_id`. `time` is omitted.
- Verifier: `data` is a mapping with a finite non-bool numeric `amount` and a non-empty `quote` mapping in which at least one entry has a finite non-bool numeric `price`.

## S5 — `cmc_exchange_map`

- Description: “Resolve CoinMarketCap exchange IDs and slugs, paginated and filterable by listing status.”
- Arguments: `listing_status` unique subset of `active`/`inactive`/`untracked`, default `["active"]`; `start` integer ≥ 1, default 1; `limit` integer 1–500, default 100; `sort` `id` or `volume_24h`, default `id`.
- Query: `listing_status` (comma-joined), `start`, `limit`, `sort`. Provider `slug`, `aux`, `crypto_id` are omitted.
- Verifier: `data` is a non-empty list; each item has a positive non-bool integer `id` and non-empty string `slug`.

## Clarifications

- **C1:** The S1 verifier shape is derived from documentation, not repository live evidence. A future live `CONTRACT_MISMATCH` requires contract review; the verifier must not be silently adapted.
- **C2:** For S3, `data` is a provider-owned results map whose category-object values contain `id` and `coins`; it is not itself the category object.
- **C3:** S4 `amount` uses strict finite numeric validation (no lax coercion from string or bool; NaN/infinity rejected).
- **C4:** The S4 USD default is handler behavior only, applied when both `convert` and `convert_id` are absent; it is not a schema default.

## Required tests (implementation phase)

Bootstrap counts 13 → 18 with the original 13 contracts pinned unchanged; strict schema snapshots; pre-network rejection with zero transport calls for every invalid case above; exact serialized query per tool including omitted provider keys, the S4 USD default and plain-decimal goldens; TTL entries; envelope/429/application-error/contract-mismatch/size-cap behavior; stdio/Streamable HTTP/in-process parity; verifier acceptance and rejection (bool, NaN, empty) cases.

S3 verifier tests must include: the documented valid results-map fixture (`{"data":{"1":{"id":"605e…","coins":[…]}}}` shape) accepted; empty outer map rejected; non-mapping value rejected; missing, empty, or non-string `id` rejected; non-list `coins` rejected; empty `coins` accepted.

## Pre-implementation contract correction — 2026-10-02

Independent verification against the current official CoinMarketCap documentation for `GET /v1/cryptocurrency/category` found that the response `data` is a results map keyed by a provider-owned key (documented example `{"data":{"1":{"id":"605e…","coins":[…]}}}`), not the category object itself. The S3 verifier, C2 and the S3 verifier tests were corrected accordingly in a follow-up to commit `73890e3`, before any E1-R implementation began. No schema, route, TTL, query serialization or other tool contract changed. The other four response shapes (S1 list with integer `id` and `quotes[]` with numeric `price`; S2 list with string `id`/`name`; S4 mapping with `amount` and `quote`; S5 list with integer `id` and string `slug`) were independently confirmed consistent with this record.

### Findings

All ten review items passed, with reproduction by the reviewer:

1. 18 tools exposed; the 13 frozen v1 tools' names, descriptions, schemas, routes and TTLs are byte-identical to `HEAD` (compared against a `git archive` extraction of `HEAD`).
2. S1–S5 names, descriptions, routes, TTLs (30/300/300/30/300 s), schemas, bounds, defaults, omitted provider parameters and query serialization match this contract.
3. 41 invalid and cross-field cases were rejected with zero upstream calls.
4. Shared `Ids` rejects `True`, `"1"` and `1.0` at runtime for `cmc_crypto_info`, `cmc_quotes_latest` and `cmc_simple_price`; its published integer schema is unchanged.
5. The S3 verifier follows C2, including acceptance of empty `coins` and rejection of the category object itself as `data`.
6. S4: strict finite `amount`, handler-only USD fallback (C4), no target schema default, plain-decimal formatting used only by S4.
7. Envelope validation, error taxonomy, 429 → `RATE_LIMITED`, the 2 MiB cap and no-caching of failures are intact for all five tools.
8. S3 lookup classification: lookup 429 → `RATE_LIMITED`; lookup 5xx, application error, contract mismatch, non-JSON, oversize or no usable id → `TRANSIENT_ERROR`, with evidence stating `/v1/cryptocurrency/category` was not called; a real malformed S3 response still yields `CONTRACT_MISMATCH`.
9. In-process, stdio and Streamable HTTP discovery agree on name, description and schema.
10. No credential, proxy, host/path/method/header control, DEX work or unrelated change; no test was weakened.

The contract's "Required tests" list is fully covered.

**S1 verifier strictness (ruled non-material):** `_is_simple_price` requires a priced quote in every list item; this record's S1 verifier sentence can be read per item or across the list. The per-item reading is a narrowing of live evidence only. It does not affect the tool's runtime contract, gives the same result for the single-id live probe, and under C1 any resulting mismatch goes to contract review rather than being adapted. Recommended: state the per-item reading explicitly at the next contract revision.
