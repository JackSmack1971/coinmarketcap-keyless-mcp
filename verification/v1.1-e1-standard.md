## Independent retrospective review — outcome: REVISE

The reviewer confirmed routes, schemas, bounds, one-tool/one-route enforcement, keyless GET-only behavior, provider-envelope/error handling, and compatibility of the original 13 contracts. One defect was reproduced:

### F1 — `cmc_price_conversion` description/schema mismatch

The tool description said it converted to “one or more target currencies”, while the schema and implementation accepted exactly one target via either `convert` or `convert_id`. Reproduction showed `convert="USD,EUR"` returned `INVALID_ARGUMENT` before any upstream call, while `convert="USD"` succeeded.

The review recommendation was **REVISE**. No production repair was made by the reviewer.

## Remediation

The implementation owner changed only the `cmc_price_conversion` description to state that it converts one source cryptocurrency to **exactly one target currency**, plus the single pinned expectation in `tests/unit/test_bootstrap.py`. Schema, validation, serialization, route, TTL, errors, mutation configuration, other tools, and the recorded REVISE finding were left unchanged.

Focused verification after the repair: 71 tests passed; Ruff check/format, full pytest (471 passed), `uv lock --check`, and `git diff --check` passed. Mutation was deferred to independent re-review because native Windows mutmut required WSL.

## Independent F1 re-review — 2026-10-02 — outcome: ACCEPT

The reviewer confirmed the F1 remediation was exactly two single-line implementation-owner changes and matched the one-target schema. In-process MCP behavior was reproduced:

- `convert="USD"` succeeds;
- `convert_id=2781` succeeds;
- `convert="USD,EUR"` is rejected as `INVALID_ARGUMENT` with zero upstream calls;
- a list value and simultaneous `convert` + `convert_id` are rejected before upstream access.

The earlier REVISE section remained intact.
